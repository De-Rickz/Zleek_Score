PRIORITY — DATA LOSS RISK: EliteZleekWriter.flush (apps/worker/ingestion/writer.py:121-137) reads AND deletes all three Redis buffers (trades:rest, trades:ws, snapshots) in one pipeline before the Postgres insert runs, so any insert failure (DB down, constraint error, timeout) silently drops that whole batch of trades and order-book snapshots; flush_loop only logs "Flush error". Unlike the items below (precision/performance), this loses data. Fix direction: only remove items after the transaction commits (e.g. LMOVE/RPOPLPUSH into a processing list, or LRANGE then LTRIM after commit).
