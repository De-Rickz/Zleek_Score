PRIORITY — DATA LOSS: the worker stops completely whenever this Mac sleeps — macOS suspends the launchd process, so the websocket, backfill, bars, features and tremor all pause together. Observed 2026-10-28: six gaps of 17–35 min in the morning plus 12:33→18:02 (5.5h), each matching `pmset -g log` exactly (last worker line 12:33:11 vs "Entering Sleep" 12:33:10; first line after 18:01:57 vs "Wake from Hibernate" 18:01:54). Fix options: keep the machine awake while plugged in (`sudo pmset -c sleep 0`, or wrap the worker in `caffeinate -s` in com.zleek.worker.plist), move the worker to an always-on host, and/or on startup backfill from MAX(trades.ts) instead of a fixed 1h. PRIORITY — DATA LOSS RISK (latent, not yet observed): clob_ws.py can't detect a dead websocket while the machine is awake. websockets.connect(ping_interval=None) (clob_ws.py:75) disables protocol keepalive; heartbeat() (clob_ws.py:37-42) sends a text "PING" every 20s but the "PONG" replies are discarded (clob_ws.py:92) and never tracked; and `await ws.recv()` (clob_ws.py:89) has no timeout. A half-open connection (Wi-Fi/network change, NAT timeout, server dropping silently) therefore blocks recv() until the OS gives up on TCP retransmits or indefinitely, with no trades captured. Predates this week (commit 821da2f, 2025-11-19); separate from Bug 3 — watch_subscription (RESUBSCRIBE_CHECK_SEC=300) only reconnects when the market selection changes, so it masks this only incidentally. Fix: track the time of the last message/PONG and reconnect if nothing arrives for ~60s (e.g. asyncio.wait_for(ws.recv(), 60)), or enable websockets' own ping_interval/ping_timeout after confirming Polymarket answers protocol pings. The heartbeat's live-trades check is what would surface it.
